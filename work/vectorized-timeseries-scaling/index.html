Scaling an energy anomaly-detection pipeline

Rewrote the data preparation of a prize-winning time-series pipeline with vectorised group transforms: 72% faster, 1.4 GB less peak memory, and a fitting bug fixed along the way.

Type
Performance engineering, machine learning
Stack
Python, pandas, NumPy, SciPy, LightGBM, XGBoost, CatBoost
Data
LEAD building-energy time series
Code
vectorized-timeseries-scaling

View the code on GitHub

Highlights

  • Loops of slice-transform-concat replaced with groupby().transform()
  • Benchmarked end to end with an automated time and memory tracker
  • Found and fixed a subset-fitting bug in the iterative version

The pipeline is the winning solution to the Large-scale Energy Anomaly Detection (LEAD) competition by Chun Fu, Pandarasamy Arjunan and Clayton Miller (BuildSys '22). It works well on benchmark data with a few hundred meters, but a practical case needed 2,000 streams, about ten times more, and the data preparation became the bottleneck.

Approach

The original code isolates each meter, slices a sub-DataFrame, applies mean imputation and Savitzky-Golay smoothing, appends the result and concatenates everything at the end. I replaced that with vectorised groupby().transform() calls, so the maths runs across all groups at once on pandas' compiled backend over contiguous arrays, following the design argument in Wes McKinney's original pandas paper. The output feeds the same LightGBM, XGBoost and CatBoost ensemble.

Results

On a standard Kaggle Linux container the vectorised version ran in 7.3 minutes instead of 26.6 and peaked 1.4 GB lower, because it stops creating and destroying temporary DataFrames. The goal was strict parity in accuracy. While checking parity I found that the iterative version was fitting on subsets of the data; with that fixed, the private leaderboard score rose from 0.933 to 0.952.
